The good news first: the architecture is sound and pleasant to work in. One command registry behind three surfaces, patch-in-place rendering that never interrupts typing, the pinned-or-loose arrow model, and driving dimensions are all well built. Nothing below needs a rewrite. The confirmed bugs are mostly one-line or one-function fixes; the critical items are about what happens to files when the app is quit, synced, or moved.

Confirmed in the running app B

Reproduced with the devtools protocol against a temporary copy of your five pages. The measurements below come from your 268-node drafting page.

B-01

Command palette input is unstyled and the list runs off the window

HighConfirmed

The stylesheet targets #switcher-input and #switcher-results, but the HTML gives them id="palette-input" and id="palette-results". The palette opens with a 153px white default input, black text, an inset border, and a results list with no height limit or scrollbar. With 50 commands it extends past the bottom of the window.

Fix: rename the two CSS selectors. Ten seconds, and the palette is the feature the README leads with.

renderer/css/app.css:383, :388 · renderer/index.html:112
B-02

Inspector sliders cannot be dragged

HighConfirmed

Every slider input event commits, commit emits doc-changed, and the inspector rebuilds its whole panel from that event. The slider under the pointer is destroyed on its own first tick. In the test, the element was gone from the document immediately after one input event. Text size, stroke width, dimension thickness and arrow thickness all move one step and then stop.

Fix: skip the inspector re-render when the change came from the inspector itself (a flag on the commit options), or update only the value labels in place during a drag. Coalescing the undo entries from the same drag belongs in the same change; see B-05.

renderer/js/inspector.js:405 (doc-changed → render) · :311 and the other range inputs
B-03

Finished tasks in a note gain an extra ~~ every time the note is edited

HighConfirmed

A done task renders as <li>☑<s>text</s></li>. When you click into the body and leave, the DOM is converted back to markdown and <s> becomes ~~text~~, so - [x] task two comes back as - [x] ~~task two~~. The next edit wraps it again. This is silent, cumulative corruption of note content.

Fix: in toMarkdown, skip the strike wrapper when the element is the direct child of a checked task li, or render done tasks with a CSS class instead of a real <s>.

renderer/js/markdown.js:26 (toMarkdown) · :166 (render)
B-04

Wikilinks to pages with &, <, > or " in the name never resolve

MediumConfirmed

inline() escapes the whole string first, then matches [[…]] on the escaped text and escapes the name again. [[Tom & Jerry]] renders as Tom &amp;amp; Jerry, is looked up as the escaped string, and is styled as a missing page.

Fix: match wikilinks and tags on the raw text and escape each piece as it is emitted, or unescape the captured name before the lookup.

renderer/js/markdown.js:92–98
B-05

Undo history fills with no-op and per-keystroke snapshots

HighConfirmed

Each beginChange stringifies the whole document (66 KB on the drafting page). Three things push snapshots far too often: focusing any text field pushes one before anything is typed, each arrow-key nudge pushes one, and each slider tick pushes one. Tabbing through a table then pressing ⌘Z appears to do nothing several times in a row.

ActionUndo entriesMemory
Click into a field, type nothing166 KB
Hold → for 20 nudges201.3 MB
One slider drag (if B-02 were fixed)≈ 1 per pixel66 KB each

Fix: push the snapshot on the first real input event rather than on focusin, and coalesce consecutive changes with the same label within about 400 ms (nudge, slider, thickness) into one entry.

renderer/js/store.js:56–71 · renderer/js/app.js:130, :404
B-06

Panning or zooming rewrites the page file and re-indexes the vault

HighConfirmed

Every wheel tick calls store.touch(), which schedules a save. The test scrolled three ticks and the file's modification time and size changed. Each save then re-reads and parses every page in the vault and ships all of them over IPC. For an iCloud vault this means every scroll uploads the page and every other Mac downloads it. With hundreds of pages the re-index becomes the slowest thing in the app.

Measured (5 pages)TimeGrows with
Write one page3.2 mspage size
Re-index whole vault2.9 ms · 85 KB over IPCvault size, every save

Fix: keep the camera per page in localStorage or the settings file instead of in the document, so viewing never dirties it. Make the index incremental: after a save, replace only that document in docIndex; do a full re-walk only on folder operations, vault change, or a file watcher event (D-03).

renderer/js/canvas.js:395, :415, :425, :1103 · renderer/js/store.js:85, :110 · main.js:152
B-07

PNG export captures the toolbar, minimap and inspector, and leaves the view changed

MediumConfirmed

exportPng zooms to fit and captures the viewport rectangle, but never adds the exporting class the PDF path uses. The floating dock, minimap and zoom chip all sit inside that rectangle. The camera is not restored afterwards, so exporting also moves you.

Fix: wrap the capture in the existing withCleanCanvas helper in export.js, which already hides chrome and restores camera and selection.

renderer/js/app.js:602 · renderer/js/export.js (withCleanCanvas)
B-08

Renderer errors never reach the terminal

MediumConfirmed

The console-message listener uses the old positional signature. Since Electron 32 it receives one details object whose level is the string 'error', so level >= 2 is always false and the handler logs nothing. The comment says this is what makes iterating less blind; right now it is blind.

Fix:

win.webContents.on('console-message', (ev) => {
  if (ev.level === 'error' || ev.level === 'warning')
    console.error(`[renderer] ${ev.message}  (${ev.sourceId}:${ev.lineNumber})`);
});

Security S

S-01

Links open arbitrary websites inside the app, and a plain link navigates the app away

CriticalConfirmed

Markdown links render as <a target="_blank">. There is no setWindowOpenHandler, so the click spawns a new Electron window showing the remote site (verified: window.open('https://example.com') produced a second window). The preload bridge was not inherited by that window, so the vault API did not leak, but the site runs in an unsandboxed app window with the app's session. There is also no will-navigate guard, so any link without a target replaces the app with the destination page. Comment text goes through the same renderer.

Fix: in createWindow:

win.webContents.setWindowOpenHandler(({ url }) => {
  if (/^https?:\/\//i.test(url)) shell.openExternal(url);
  return { action: 'deny' };
});
win.webContents.on('will-navigate', (e) => e.preventDefault());

And in the renderer's click handler, route a[href] through window.api.openExternal so the anchor never navigates.

main.js:349 · renderer/js/markdown.js:105 · renderer/js/app.js click handler

Data safety D

The README's promise is "plain files you own, synced by iCloud or Dropbox". These are the gaps between that promise and what the file layer does.

D-01

Page writes are not atomic

CriticalFrom code

page:write writes straight over the existing file. A crash, a kill, or a power cut during the write leaves a truncated JSON file, and readIndex then silently skips it, so the page vanishes from the sidebar.

Fix: write to <file>.tmp in the same directory, then fs.rename over the original. Keep the previous version as .bak if you want belt and braces.

main.js:224
D-02

Quitting soon after typing can drop the last edits

CriticalFrom code

Saves are debounced by 550 ms. On close, beforeunload fires store.save() but cannot wait for it; the renderer tears down and the main process may exit before the async write lands. Type a sentence, press ⌘Q, and the sentence may not be on disk.

Fix: handle before-quit and window close in main: prevent the default, ask the renderer for the dirty document over IPC, write it synchronously, then quit. Or expose a sendSync flush in the preload used only from beforeunload.

renderer/js/app.js:645 · renderer/js/store.js:103 · main.js app lifecycle
D-03

Changes made outside the app are never seen, and get overwritten

CriticalFrom code

Nothing watches the vault. If iCloud brings in an edit from another Mac while a page is open here, the next autosave writes this Mac's stale copy over it. New pages synced in do not appear until something triggers a save. This is the exact scenario the README advertises.

Fix: fs.watch the vault recursively (macOS supports it natively) with a short debounce. On a change to a file that is not the open page, refresh that entry in the index. On a change to the open page with no local edits, reload it. On a change to the open page with local edits, write the local copy as Name (conflict YYYY-MM-DD).canvaslide.json and toast, the way Obsidian and Syncthing do.

main.js (no watcher) · renderer/js/store.js refreshIndex
D-04

Images are stored as absolute paths

CriticalFrom code

A pasted image is saved into assets/ correctly, but the node stores file:///Users/leo/Documents/CanvasLide/assets/…. Open the same vault on a Mac with a different username, move the vault folder, or use "Change Vault Folder" after moving files, and every image is broken. The JSON Canvas exporter already strips the prefix, which shows the intent.

Fix: store assets/x.png in the document and resolve to a URL at render time in nodes.inner. Migrate on load: if src starts with file://, keep the part after /assets/.

renderer/js/app.js:465 · renderer/js/nodes.js image case · renderer/js/jsoncanvas.js

CriticalFrom code

The confirm dialog is the only protection. A slip on the small × that appears on hover over every page row is unrecoverable.

Fix: move the file to .trash/ inside the vault instead. The vault walker already ignores dot-folders, so nothing else changes. Add "Empty trash" to the palette.

Keyboard and menu K

These could not be reproduced by script because macOS blocks synthetic keystrokes without accessibility permission. Typing ! in any note will show whether K-01 is real on your machine.

K-01

Typing ! or @ in a text field zooms the canvas

HighFrom code

The View menu binds Zoom to Fit and Zoom to Selection to Shift+1 and Shift+2. On macOS, application-menu key equivalents are handled before the web page sees the key, so those shortcuts fire even while a note has focus. On a US layout those chords are ! and @. The renderer already handles ⇧1 and ⇧2 itself, correctly guarded by isTyping(), so the menu accelerators are redundant.

Fix: drop the accelerator from those two menu items and leave the renderer's handler in charge. Show the shortcut in the label text if you want it visible in the menu.

main.js:419–420 · renderer/js/app.js wireKeys
K-02

⌘Z while typing performs document undo instead of text undo

HighFrom code

Edit → Undo and Redo are custom items that call store.undo(). The renderer deliberately leaves ⌘Z alone while typing so the browser's native text undo works, but the menu takes the keystroke first. The result: the whole document snapshot is restored underneath a field you are still editing, and the next keystroke writes the field's DOM text back over it.

Fix: use { role: 'undo' } and { role: 'redo' } in the menu, and in the renderer intercept ⌘Z on window only when not typing (already the case). Native undo then reaches the focused field, and canvas undo keeps working when nothing has focus.

main.js:405–406 · renderer/js/app.js wireKeys

Performance and structure P

Measured on the 268-node, 112-arrow drafting page: a full render took 3.8 ms and a drag repaint 1.9 ms. Nothing here hurts today; these are the places that will scale badly.

P-01

Node lookups by querySelector inside loops

LowFrom code

render, paintOnly and a dozen call sites find a node's element with an attribute selector, so a repaint of n nodes is n scans of the layer. Also nodeById is a linear find called from hot paths such as arrow rendering.

Fix: keep a Map from id to element in nodes.js and a Map from id to node in the store, rebuilt on doc-changed.

renderer/js/canvas.js:853 and similar · renderer/js/store.js nodeById
P-02

Sidebar rebuilds on every save and re-sorts by last edit

MediumFrom code

Each autosave emits vault-changed, which sets innerHTML = '' on the page list, losing scroll position, and the list is sorted by updated, so the page you are editing jumps to the top of its folder on every edit. That makes the tree feel unstable exactly while you are using it.

Fix: sort alphabetically by default with an optional "recent" sort, and only re-render the sidebar when names, folders or page count change.

main.js:131 · renderer/js/sidebar.js:18
P-03

Graph view redraws at 60 fps forever while open

LowFrom code

tick stops simulating when the layout settles but keeps rebuilding the SVG every frame.

Fix: only call draw() when the simulation stepped, a drag or pan happened, or hover changed.

renderer/js/graph.js:151
P-04

Full canvas re-render on title keystrokes and after every save

LowFrom code

Renaming the page commits on every keystroke, and vault-changed is also wired to App.canvas.render(). Neither needs to repaint the nodes.

Product improvements U

U-01

A drawing set with mixed sheet sizes prints every sheet at the first one's size

HighFrom code

printBoxes derives the page size from the first section and scales every later section to fit it. An A3 landscape followed by an A4 portrait produces two A3 pages with the second drawing letterboxed. That contradicts the README's "a PDF whose page really is A3".

Fix: Chromium supports named pages. Give each .pdf-page its own page: sheet3 and emit @page sheet3 { size: … } per section, and drop the shared @page rule.

renderer/js/export.js:136 (printBoxes), buildPrintDoc
U-02

The link card exists but nothing creates one

MediumFrom code

There is a full link node type with rendering and open-in-browser, reachable only through JSON Canvas import. Pasting a URL today makes a note whose title is the URL.

Fix: add "Link" to the insert list; when pasted text is a single URL, create a link card; on drop of .md or .txt, create a note.

Renaming a page does not update links to it

MediumFrom code

Every [[Old name]] elsewhere in the vault becomes a missing link. Obsidian offers to rewrite them, and it is the reason people trust wikilinks. The rename is also not undoable.

U-11

No tests for the two pure, fragile modules

MediumFrom code

Fix: node --test with jsdom for the markdown round trip, plus fixtures for an Obsidian-authored .canvas file.

Cleanups C

C-01

The raster PDF pipeline is dead code

LowFrom code

Since the switch to printToPDF, all of pdf.js, jpegSize, the capture:region and pdf:save handlers, captureRegion and savePdf in the preload, and captureBox in export.js are unreachable. The preload also exposes readAll and listPages, which nothing calls.

Fix: delete them, and keep withCleanCanvas for B-07. Fewer IPC entry points is also a smaller attack surface.

C-02

Stale CSS and README

LowFrom code

The .handle, .port, .align-bar rules and #dock refer to DOM that no longer exists (the overlay draws handles in SVG now). node._scale and void prev in resizeTo are leftovers. The README's "Not there yet" section still says PDF output rasterises and text is not selectable, which stopped being true when vector printing landed.

renderer/css/app.css:274–285, :563 · renderer/js/canvas.js resizeTo · README.md:224
C-03

Mixed icon styles

LowFrom code

The comment in util.js says inline SVG icons are sharper than emoji, but only the folder icon was converted; the toolbar is still emoji run through a grayscale filter, and renders differently per macOS version.

Fix: a set of 14 one-colour SVG icons in App.icons, which would also let the active tool take the accent colour properly.

C-04

Distribution

LowFrom code

The packaged app is unsigned and not notarised, so on another Mac it opens with the Gatekeeper warning. If it is only for you this is fine; if it goes to anyone else, @electron/osx-sign and @electron/notarize slot into the existing package script.

Suggested order

  1. One afternoon, all confirmed: B-01 palette CSS, B-08 console handler, K-01 and K-02 menu accelerators, S-01 window-open guard, B-07 PNG chrome. Five files, no design decisions.
  2. Data layer: D-01 atomic writes, D-02 flush on quit, D-05 trash folder, D-04 relative asset paths with migration. This is what makes "your files, your folder" true.
  3. Editing feel: B-03 strike round trip, B-04 escaping, B-05 undo coalescing, B-02 inspector re-render. B-02 and B-05 are one change.
  4. Sync: B-06 camera out of the document and incremental index, then D-03 the watcher with conflict copies. Do B-06 first or the watcher will fire on every scroll.
  5. Then the product items, U-01 mixed sheet sizes first since it breaks a documented promise, and U-11 tests before touching markdown.js again.
